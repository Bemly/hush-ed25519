# hush-ed25519

Ed25519 (RFC 8032) signing and verification in pure shell — no compiled
binaries, no python, no openssl. Runs on a stock `busybox:musl` image where the
only tools available are the BusyBox applets themselves.

Same shape as [hush-json](https://github.com/Bemly/hush-json): a shell facade
(`lib/ed25519.sh`) plus an awk compute engine (`lib/awk/ed25519_engine.awk`).

contended host can be 2–3× slower.

## Quick start

```sh
. ./lib/ed25519.sh

# Sign a file (seed = 32-byte hex)
ed25519_sign_hex 9d61b19deffd5a60ba844af492ec2cc44449c5697b326919703bac031cae7f60 msg.bin
# → e5564300c360ac729086e2cc806e828a... (128 hex chars)

# Verify
ed25519_verify_hex d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a \
	msg.bin e5564300...100b && echo valid

# Derive a public key
ed25519_pub_hex 9d61b19deffd5a60ba844af492ec2cc44449c5697b326919703bac031cae7f60
# → d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a
```

Everything is fed through pipes/files — no binary blob ever lands in a shell
variable, because shell strings stop at NUL bytes.

## API

| Function | Output | Notes |
|---|---|---|
| `ed25519_sign_hex <seed_hex64> <msg_file\|->` | 128 lowercase hex | deterministic signature |
| `ed25519_verify_hex <pub_hex64> <msg_file\|-> <sig_hex128>` | exit 0 valid / 1 invalid | canonical checks enforced |
| `ed25519_pub_hex <seed_hex64>` | 64 lowercase hex | public key for a seed |
| `ed25519_seed_hex <secret>` | 64 lowercase hex | repeat secret to ≥32 bytes, truncate to 32 |
| `ed25519_sign_secret <secret> <msg>` | 128 lowercase hex | `seed_hex` + `sign_hex` |
| `ed25519_verify_secret <secret> <msg> <sig>` | exit 0 / 1 | `seed_hex` → pub → verify |
| `ed_sign`, `ed_verify`, `ed_pub`, `ed_seed` | aliases | shorter names |

- `-` as message path reads stdin.
- Seeds and signatures are hex in, hex out; uppercase hex is accepted.
- On failure the function returns non-zero and sets `_ED25519_ERROR`.
- Temporaries live in `${TMPDIR:-/tmp}/ed25519.$$` and are removed on return;
  concurrent calls from the same PID are not supported (each shell process has
  its own PID, so CGI workers are fine).

### QQ Bot secret derivation

QQ derives the callback signing key from the bot secret by repeating it until
it is at least 32 bytes long and truncating to 32 — that is exactly
`ed25519_seed_hex`, exposed as `ed25519_sign_secret`:

```sh
sig="$(ed25519_sign_secret "$QQBOT_APP_SECRET" "$payload_file")"
```

Keep the secret out of `argv` (use the environment) so it never shows up in
`ps`; the library itself takes it as a parameter and never logs it.

## How it works

| Layer | Choice |
|---|---|
| Field | base 2^21, 13 limbs; `2^255 ≡ 19`, carry chain then conditional subtract `p` |
| Point arithmetic | extended coordinates `(X,Y,Z,T)`, unified addition (works for doubling) |
| Scalar mult | 4-bit window, 15 precomputed points, table built once per call |
| Verify | `[S]B == R + [h]A`, interleaved double-scalar multiply; `A` unpacked to `(−X, Y, Z, −T)` |
| Packing | `fe_pack` does a full canonical reduction and forces the sign bit |
| Scalars | 16 × 16-bit limbs, shift-and-subtract reduction mod `L`, `S < L` enforced |
| SHA-512 | `printf '%s' <bytes> \| sha512sum` |
| Hex ↔ bytes | `xxd -r -p` / `xxd -p` |

Rejected inputs (all return "invalid", never an error): `S >= L`,
non-canonical `y >= p`, and the identity public key (small-order forgery).

## BusyBox awk caveats

The engine is written for **BusyBox awk only** — it relies on `and/or/xor/…`
being unnecessary but does rely on:

- `sprintf("%02x")` for byte output; `%d`/`%x` truncate at 32 bits, so no large
  integer ever goes through them (`%.0f` is used instead).
- doubles as exact integers: every accumulator stays below 2^53 (13 limbs of
  2^21 ⇒ `13 · 2^42 ≈ 2^45.7`). No reduction is skipped — an unreduced
  accumulator silently turns into `inf`.
- arrays passed to functions as parameters (BusyBox awk makes them local).
- `substr`/`index` never touch hex parsing in hot loops; hex is converted by
  `xxd`, which is ~2 orders of magnitude faster than per-character awk parsing.

`gawk --posix` should also work, but only BusyBox is tested and supported.

## Testing

```sh
docker run --rm -v "$PWD":/w busybox:musl sh /w/test/run.sh
```

The suite covers 17 vectors (sign, verify, tampered signature, tampered
message, wrong key), key derivation, stdin piping, error paths, canonical
encoding edge cases and temp-file hygiene.

## Performance notes

- One signature costs two scalar multiplications (`[a]B` for the public key and
  `[r]B` for `R`), one verification costs two as well (interleaved).
- Removing the public-key multiplication by caching `A` for a fixed secret
  saves ~0.6 s, but the library stays stateless on purpose.
- `fe_mul` dominates: 13×13 limb products with a folding factor for the limbs
  above bit 255.
